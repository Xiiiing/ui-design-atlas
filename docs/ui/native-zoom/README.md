# 原生缩放与真实滚动条下的预览稳定性

本轮处理的是整幅预览 UI 的尺寸振荡。用户确认 Edge 页面缩放 100% 正常，110% 后静置也抖动；Windows 显示缩放为 100%，鼠标移到页面外仍发生。

## 原因与复现

原先读取整数 `clientWidth/clientHeight`，再将它们写回画布和 iframe 的像素尺寸。原生缩放下容器实际宽高可能是小数，整数回写产生溢出。经典滚动条出现后可用宽高缩小，ResizeObserver 再缩小画布，滚动条消失后又放大，形成逐帧循环。

Playwright 默认在无头模式加入 `--hide-scrollbars`。此前测试没有保留滚动条，遗漏了该循环。本轮测试明确移除这个默认参数，启动完整 Chromium，通过浏览器设置 API 改变原生页面缩放，并验证 DPR，未用 CSS zoom、捏合模拟或单纯改变 viewport 代替。

同一旧版本 `66bb953`、1910×873 浏览器窗口、110% 原生缩放下，90 帧触发 90 次 iframe resize，可用宽高在 1727×572 与 1713×558 CSS px 之间反复切换。1440px 窗口的 150%、1273px 窗口的 125% 也复现。

## 修复与结果

自动画布与 iframe 以百分比匹配真实容器；设备模式用 CSS `min()` 限制宽度，再从实际计算宽度得到缩放比例，高度也由百分比承载。原始尺寸模式继续允许必要滚动，不关闭浏览器滚动条，不停止演示动画。

| 条件                          | 修复前       | 修复后       |
| ----------------------------- | ------------ | ------------ |
| 110%、90 帧中的 iframe resize | 90 次        | 0 次         |
| 同一静置区间的画布状态        | 两组反复切换 | 一组稳定状态 |
| iframe 内部经典滚动条         | 显示         | 显示         |

[完整对比及逐倍率数据](measurements.json)、[Linux Edge 110% 截图](edge-110.png)。每个倍率的前后状态比较在各自的静置区间内进行；主动改变缩放、窗口、设备或全屏产生的正常尺寸变化不计为抖动。

## 验收

- 完整 Chromium 原生设置：100%、110%、125%、150%、175%、200%、返回 100% 再到 110%。同一页面实时切换，也验证在 110% 重新载入。
- 1910×873、1440×655、900×900 浏览器窗口，保留经典滚动条；自动、375/768px 设备、原始尺寸、详情、全屏及退出。
- 静置逐帧比较画布、卡片、内部根节点和滚动位置，要求零 iframe resize；缩放和控制操作不增加文档请求，原文档和表单输入保留。
- 三引擎既有关键流程与完整生产测试继续执行。另在临时解压的 Microsoft Edge 155.0.4283.62（Linux）中实际执行相同原生缩放与 90 帧检查；没有安装到系统或修改依赖版本。尚未在原生 Windows 上人工验证。

测试见 `tests/native-zoom.spec.mjs` 与 `tests/native-zoom.mjs`。浏览器窗口尺寸包含浏览器 UI，记录与截图以实际网页尺寸及 DPR 为准。

本地最终验证：`npm run check` 通过（严格类型检查与 12 项单元测试）；`npm test` 先完成生产构建，再通过全部 156 项浏览器测试（Chromium 140、Firefox 8、WebKit 8），无跳过或 flaky；`npm run test:dev` 的热更新验收通过。原生缩放、跨浏览器与沉浸预览的 31 项定向回归也通过。独立 Linux Edge 与 Chromium 的各 8 轮原生倍率检查，每轮 90 帧均为零 resize、一组稳定状态。
