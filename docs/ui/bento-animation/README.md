# Bento Grid 通知插入稳定性

用户反馈 `#block/magicui-bento-grid?lang=zh-CN` 在 Edge、100% 缩放下，静置时卡片内部仍不断跳动。线上入口脚本与 PR #48 的构建一致；本次定位到具体动画内部。

通知背景原来使用 CSS `scale-75`，已有通知使用 Motion 的 `layout` 投影。每秒插入新通知时，CSS 祖先缩放没有进入投影坐标，导致已有通知先突跳 18px，再继续弹簧动画。连续五次插入均复现。去掉背景缩放作对照，插入瞬间的突跳消失；将同样的缩放移入 Motion 的祖先节点后，原有尺寸及悬停行为可以保留。

## 实测结果

同为 Chromium、1440×900、中文、正常浏览器时钟，连续记录五次新增通知：

| 场景                 | 插入瞬间已有通知的纵向位移 |
| -------------------- | -------------------------- |
| 修复前，75% 背景缩放 | 五次均为 18px              |
| 修复后，75% 背景缩放 | 五次均为 0px               |
| 修复后，90% 悬停缩放 | 最大浮点误差约 0.000031px  |

[插入帧与首段轨迹数据](measurements.json)，[修复后的深色预览](preview-dark.png)。这是已有通知在插入瞬间的位移，后续平滑移动仍然保留。

## 修复

只调整 Bento 演示包装：通知背景由 Motion 管理 75% 默认比例与 90% 悬停比例，列表与背景共享缩放坐标。保留通知内容、间隔、弹簧进入、跑马灯、日历、连线及卡片悬停。触屏按实际 hover 能力处理，点击不会锁定桌面悬停比例。未修改归档的上游 vendor 文件或升级依赖。

## 验证方法

- 对现有通知逐帧记录纵坐标，在新增条目那一帧比较位移，不能仅比较 iframe 或卡片外框。
- 生产构建中记录真实动画帧，保存修复前后插入附近的数据。原来的 18px 瞬移被消除；首帧仍可能有正常的连续动画位移，不把它等同于要求列表静止。
- 自动测试在导航前安装浏览器时钟，按固定 16ms 帧步推进多次插入，要求插入帧位移小于 4px，同时断言累计位移大于 100px、条目持续增加，证明动画仍在运行。
- 中英文、明暗、静置、悬停、375px 触屏；Chromium、Firefox、WebKit 均执行通知测试。Firefox 无头环境不报告 hover 能力时，按其真实媒体查询结果验证 75% 比例。
- 全程断言画布、四张卡片、iframe 文档及滚动位置保持不变。沿用详情、全屏及源码交付的完整回归测试。

本地没有 Microsoft Edge 可执行文件，用户的 Edge 场景由 Chromium 复现，另执行 Firefox、WebKit；不声称已在原生 Edge 上人工验收。
