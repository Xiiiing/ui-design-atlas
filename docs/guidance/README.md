# 设计指导、资源导航与提示词组合器

图鉴有两种使用方式：体验界面，再复用其设计与代码；或者先找到提示词、Skill、规范与检查清单，再将它们组合成项目要求。

## 浏览与使用

- `#guidance`：提示词、Skills、设计规范与检查清单。搜索、类型及用途筛选保存在 URL，支持刷新、历史和分享。详情为阅读布局，正文按需读取。
- `#tools`：八个仓库入口，区分组件库、Skills 集合、规范集合和学习资料。点击进入详情可查看原始仓库与已整理内容。
- `#compose`：填写项目需求，选择基础模板、最多一份设计规范、一个界面参考及多项检查和 Skills。输出可直接编辑、复制和导出 Markdown。
- 详情中的“关联界面”和界面说明中的“相关设计指导”相互链接。“加入提示词组合”将选择交给组合器，已有需求与编辑文本保留。

普通对话使用本站整理的任务要点；编程助手模式提供完整 Skill 原文与配套文件包。复制原文、下载 ZIP 或在提示词中提及 Skill，不会自动安装或执行 Skill。是否能运行项目、读取文件或查看页面取决于使用环境。

## 首批内容与验证标识

首批为 13 项指导：4 项提示词、5 项 Skills、2 项设计分析、2 项检查清单；另有 8 个仓库入口。视觉品质追加语保留用户原句及整理后的版本。获奖网站仅作为品质参考，不保证生成结果。

“内容已核对”表示本次核对了说明、文件与适用范围；“AI 生成效果尚未验证”表示没有完成真实 AI 生成任务的效果验收。浏览器测试、构建通过和个人勾选均不改变这个状态。清单勾选仅记录当前浏览器的个人进度。

上游文件保留原始语言，中文和英文摘要为本站整理。Baseline UI 对 Tailwind、React 动效及组件原语有明确偏好，应先核对技术栈。Linear 与 Vercel 条目是 VoltAgent 的第三方网站设计分析，不是品牌发布的官方规范；色板与字体摘要为本站整理，字体与品牌素材不随规范下载包分发。

## 组合与草稿

组合顺序为需求与约束、设计规范、界面参考、任务要求、交付自检。用户明确约束优先。选择规范后，参考界面用于信息组织、布局关系与交互；未选择规范时，可复用该界面的视觉提示词。

选择变化不会覆盖手动编辑的输出；仅点击“重新生成（替换当前文本）”时替换。异步读取期间若用户继续修改，保留现有文本并提示重新生成。读取失败可重试。

草稿仅保存在当前浏览器，不将需求正文放入 URL；打开带选择参数的组合链接后只消费一次。语言切换保留原始需求和输出，重新生成才使用当前语言。存储失败时会提示，当前会话中仍可编辑、复制和导出；清除浏览器数据会丢失本地草稿。本站不调用模型接口或上传用户需求。

## 收藏与兼容

界面、指导和仓库入口共用收藏，可按内容范围查看。原有 `component/block/page/case:id` 键不变，新键为 `guidance:id` 和 `tool:id`。`#favorites?type=component` 等旧链接继续表示界面范围。

继续导入版本 1 的 UI 收藏备份；版本 2 包含所有内容类型。导入先完整校验，再合并去重；无效键使整份拒绝，存储失败单独提示。旧版网站不具备版本 2 导入能力。收藏不会包含组合草稿或需求正文。

## 内容维护

`content/guidance.json` 是指导索引，`content/tools.json` 是仓库入口；正文放在 `content/guidance/<id>.json`。增加内容时同时提供中英文名称、说明、用途与正文，选择明确的指导类型。关联界面用现有 `type:id`，关联仓库用入口 ID；反向关系由索引生成，不重复维护。

提示词正文可以使用 `{{requirements}}`、`{{audience}}`、`{{technology}}`、`{{direction}}`。组合器使用独立的任务要点，避免重复拼接整个表单。检查清单提供对应语言的逐项要求。新增条目后同步调整首批清单与相应数量测试。

```json
{
  "id": "my-prompt",
  "kind": "prompt",
  "name": { "zh-CN": "我的提示词", "en": "My prompt" },
  "description": {
    "zh-CN": "明确用途与边界。",
    "en": "Describe purpose and boundaries."
  },
  "purposes": ["website", "review"],
  "related": ["block:magicui-bento-grid"],
  "aliases": ["网站", "website"],
  "checked": false,
  "effect": "unverified"
}
```

对应正文包含双语 `body`、`task`、`usage`；需要清单时提供 `checks`，保留原句时提供 `original`。设计分析另提供参考色板和排版摘要。完成内容核对后再设置 `checked: true`，不能据此宣称生成效果验证通过。

更新时从确定提交获取原文件，保留 LICENSE，核对所有相对 Markdown 引用，将必要文件加入对应条目清单，并更新 `content/guidance-sources.json` 中的提交与 SHA-256。不要为跳过检查而只更新哈希；先核对文案、规则、技术前提和依赖变化。

开发与生产共用文件校验和 ZIP 生成。指导正文接口为 `guidance/<id>.json`，完整包为 `downloads/guidance/<id>.zip`；包内有原始入口、必要配套文件、LICENSE 及使用说明。本站原创文本包保留双语内容和清单，不新增许可条款。只按明确文件清单交付；未知文件、路径越界、越界符号链接、缺失引用及快照修改均被拒绝。

开发模式修改索引、正文或规范后自动刷新，并使生成接口失效。无效目录明确报错，不继续返回旧内容。派生产物只进入开发临时目录或 `dist`，不回写源码。

## 工程验证与发布

执行 `npm run verify`，完成严格类型检查、单元测试、生产构建、Chromium 全量测试、Firefox/WebKit 关键流程和隔离开发热更新验收。主文档只保留收藏身份与反向关联所需的轻量索引，完整搜索、扩展收藏、阅读工具与组合器按使用场景加载；沿用 190,000 字节 gzip 的启动预算。

验收覆盖四种宽度、两种语言及两种主题，截图与尺寸记录保存在浏览器测试产物中。该验证不代表真实 AI 生成效果验证。

PR 必需 CI 成功后 Merge 合并，沿用既有 Pages 流程；交付时记录确切合并提交和部署运行。若需回退，通过回退 PR 与同一流程处理，不强推、不改写历史。后续线上体验评测由用户执行。
